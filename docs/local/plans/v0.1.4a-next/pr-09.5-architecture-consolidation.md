## Global Constraints

- Keep the seven contexts: Identity, Inventory, Monitoring, Configuration, Runtime, Health and Operations.
- Treat Application Host, CLI, platform/persistence, protocol servers and test infrastructure as supporting boundaries, not business contexts.
- The source tree is flexible; introduce a layer or subpackage only where a real contract, platform boundary or capability cohesion justifies it.
- Preserve the single operational SQLite database, schema versions 1–14 and migration order, WAL/locking policy, CAS/revisions and current cross-table atomic writes.
- Preserve CLI command/flag/output/exit behavior, enrollment/recovery, protected credentials, discovery history/completeness, monitoring profiles, receiver ownership, Collector and Supervisor lifecycle, activation/LKG, managed dependencies, Health truth and Operations replay/audit/outbox.
- Do not combine source moves with feature work, behavior changes, schema redesign, new protocol, Core security policy or lifecycle-owner changes.
- Keep OTel receiver/processing/export behavior in the Collector; do not add another discovery, event, plugin, queue or OpAMP engine.
- Do not modify `docs/shared/` or Core production code. The pinned shared policy at submodule commit `c4cd59a9bcaaf0735c3107424f1be98fc498670a` was read and compared with `docs/local/development/coding-policy.md`; the local 450-LOC ceiling is stricter than, and consistent with, the shared 300–400 LOC preference plus justification for larger files.
- Preserve all pre-existing worktree changes. The planning checkout `feat/pr-07-opamp` at `3441c5a705c1d9577e2c1ee683622b562d040296` contained unrelated dirty source and scratch artifacts and remains untouched. PR-09.5a used a separate clean worktree based on `b2599b8`; it merged as `79bb5a3092f55b3645d667d4f5481bde6c44700e`. PR-09.5b uses a fresh worktree and branch based on that updated integration head.

## Review Focus

- A file may combine policy and persistence even if its package name looks like an adapter; trace the owning transaction and active callers before moving it.
- `agentstate` is the migration hub for multiple contexts; splitting one transaction across repositories must not replace atomicity with event ordering.
- `cmd/agentctl` has command presentation, composition and workflows; preserve observable CLI behavior while moving only business decisions.
- Runtime contains two different Collector control implementations (legacy Agent supervisor and OpAMP Supervisor); exactly one may own a given installation.
- Protocol, platform and test packages may be mistaken for business contexts; keep service/system boundaries distinct and do not make Mock Core the production authority.
