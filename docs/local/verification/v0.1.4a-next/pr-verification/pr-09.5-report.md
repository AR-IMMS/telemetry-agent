## PR-09.5a source characterization (historical; integrated)

### CLI and host behavior

- `go run ./cmd/agentctl help` exits 0 and prints root help. `go run ./cmd/agentctl --help` is not a supported alias: it reports unknown command `"--help"` and the dispatcher returns usage exit 2. Existing `cmd/agentctl/help_test.go` snapshots exact root output and exit behavior; `dependency_help_test.go` snapshots the dependency subcommand.
- Root help lists `bootstrap`, `dependency`, `integration`, `run`, `inventory`, `discovery`, `status`, `doctor`, `enroll`, `install`, `uninstall`, and `help`. The dispatcher also accepts `service`, which is intentionally absent from root help today. Windows `service` requires `--state-path`, rejects positional arguments, and delegates stop/shutdown to SCM cancellation and a wait for the Agent runtime. The non-Windows implementation returns usage exit 2. Keep this behavior until the CLI slice characterizes each moved workflow.
- Baseline command-specific options read from the actual flag declarations and guarded `--help` invocations: `bootstrap` (`--config-root`, `--install-dir`, `--config-path`, `--state-path`, `--gateway-endpoint`, `--validation-endpoint`, `--timeout`); `run` (`--state-path`); `dependency` subcommands (including `status`, `pending`, `configure`, `disable`, and `uninstall` state-path/name options); `integration` (state path, ID, definition/version, settings, enabled, history limit; catalog ID/version/output; template ID/JSON/file/output); `inventory` (state path, `--active-only`); `discovery proposals` (state path, proposal ID/input); `status`/`doctor` (`--endpoint`); `enroll` (`--core-origin`, state path, `--resume`, `--re-enroll`); `install` (config root, gateway, OpAMP URL, explicit legacy-owner opt-out, validation endpoint, timeout); `uninstall` (state path, timeout); hidden Windows `service` (state path). The baseline binary was built from the checkpoint tree with no CLI source edits. All `--help` probes returned before side effects; invalid/help paths use the existing usage exit 2 except the explicit root `help` command.
- `internal/app.RunRuntime` validates the runtime context/builder, creates one advisory dispatcher, composes components, requires a reconciler and recovery recorder, then delegates Collector lifecycle. Reconciliation polls every 15 seconds; inventory polls every 30 seconds. Optional Operations and Agent control loops share a cancellation context. Inventory/template/proposal loops stop when reconciliation returns; post-commit events are wakeups, not authority.

**Coordinator contract:** `internal/platform/sqlite/migrate.Migration` holds one global version, diagnostic name, and owner-supplied `func(*sql.DB) error`. `migrate.Apply` validates the complete contiguous 1-based registry before executing any callback, runs entries in registration order, stops at the first error, and wraps the owner error with version/name while preserving `errors.Is`. It does not sort/skip entries, own DDL, inspect business tables, or wrap a new transaction around migrations. Each owner migration retains its existing idempotency and transaction boundary. Version 1 historically consists of autocommit setup statements; it must not be described as an atomic migration.

At the 09.5a checkpoint, the ordered definitions were all assembled at `agentstate.ensureSQLiteSchema`. In PR-09.5b, callbacks for versions 2, 5 and 10–11 now live with their Identity/Inventory owners; `agentstate.ensureSQLiteSchema` still assembles the global sequence as a transitional registration seam. The remaining definitions and final application-composition registration move with later owner slices. Do not let `internal/platform/sqlite` import business contexts or replace `agentstate` with another hub.
