# Agent Operations Contracts

**Version:** `ar-imms.operation.request.v1` / `ar-imms.operation.result.v1`  
**Status:** Agent-local implementation contract for PR-09 Phase 1; production Core interoperability remains a separately approved integration.

Core is the business authorization authority. The Agent validates message version, authenticated broker scope, installation and binding identity, expiry, supported operation type, target identity, and local execution safety. `requested_by` and `authorization_ref` are audit correlations only; the Agent does not evaluate human roles.

The read-only catalog is `agent.diagnostics`, `container.inspect`, and `dependency.inspect`. `container.restart` is a narrowly gated Phase 2 operation: it is absent from runtime registration unless the Agent process starts with `AR_IMMS_OPERATIONS_CONTAINER_RESTART_ENABLED=true`, and each target must carry the exact label `ar-imms.operations.container-restart.enabled=true`. The target must be a full Docker ID and running at fresh pre-action inspection. The Agent issues one restart call, never retries it, and verifies the same ID using a newer Docker `StartedAt` timestamp or an increased restart count. Docker does not increment `RestartCount` for the manual restart path on every engine; verification therefore accepts the changed start time as evidence. If neither signal verifies the action, the result is `UNKNOWN`. `UNKNOWN` executions are persisted as `UNKNOWN_OUTCOME` and never replayed as mutations. Docker socket access is host-level privilege; the label is an eligibility signal, not an OS isolation boundary. `container.logs` remains excluded because its sensitive-data exposure policy is unresolved.

The schemas reject unknown fields and bound envelopes, target identifiers, parameters, and results. Operation IDs are immutable. Fingerprints use JSON encoding of the typed envelope with parameter object keys canonicalized by Go's JSON encoder; semantically different field values remain different requests. A repeated ID and fingerprint reuses its stored outcome; a repeated ID with a different fingerprint is rejected. Actor and authorization references are retained in the local audit trail for correlation and are not interpreted as business permissions.

Operations uses a separate installation-scoped process lock before startup recovery or command consumption. After acquiring it, leftover `RUNNING` read-only records are finalized as `FAILED` / `EXECUTION_INTERRUPTED`; interrupted `container.restart` records are finalized as `UNKNOWN` / `OPERATION_OUTCOME_UNKNOWN`. Both are committed with audit and outbox evidence. A repeated operation ID reuses its terminal result and never repeats a restart. Handler execution is bounded to 30 seconds and JetStream ACK progress is extended during work.

See the [request schema](operation-request-v1.schema.json), [result schema](operation-result-v1.schema.json), [broker binding v1 schema](broker-binding-v1.schema.json), and [JetStream contract](transport.md). These local specifications do not modify or supersede `docs/shared/` contracts.
